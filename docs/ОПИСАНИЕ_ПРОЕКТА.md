# Описание проекта

Составлено до начала разработки, по структуре из урока CLm04.

---

## Название

**Ширма** — обезличивает файлы перед тем, как показать их постороннему.

## Проблема

Чтобы починить чужую программу, надо увидеть её логи, конфиги и код. А в
логах живут ключи, пароли, телефоны, адреса серверов и фамилии сотрудников.
Получается тупик, который стоит денег обеим сторонам:

- заказчик не даёт доступ, потому что боится утечки, — и работа не начинается;
- либо даёт как есть, и его секреты расходятся по чужим ноутбукам и чатам.

Обычное решение — замазать всё звёздочками — ломает саму возможность
диагностики: пропадают связи между кусками. Если один и тот же ключ в десяти
местах превратился в `***`, уже не понять, один это ключ или десять разных,
и какой из них истёк.

Проблема не выдуманная: это первый вопрос, который задают заказчики на бирже,
и он прямо записан в моей услуге по починке чужого кода.

## Пользователь

1. **Разработчик-фрилансер**, которому прислали чужую систему на разбор. Ему
   нужно показать кусок лога в переписке, чате поддержки или нейросети — и не
   раздать при этом клиентские секреты.
2. **Заказчик**, который хочет отдать файлы на диагностику, но обязан
   соблюдать NDA и закон о персональных данных.
3. **Любой, кто вставляет логи в чат с ИИ.** Это уже массовая привычка, и
   вместе с трассировкой туда улетают токены и адреса баз.

## Основная функция

**Вход:** файл или папка — логи, исходники, конфиги, выгрузки (текстовые
форматы).

**Что происходит:** каждое чувствительное значение заменяется устойчивой
меткой. Устойчивой — значит одна и та же компания везде становится
`КОМПАНИЯ_1`, один и тот же ключ — `KEY_1`, в том числе в разных файлах.
Смысл и связи сохраняются, данные — нет.

**Выход:** обезличенная копия + словарь замен, который остаётся у владельца
и никуда не отправляется. По словарю ответ, полученный от постороннего,
разворачивается обратно в настоящие имена и ключи.

**Инструменты:** набор шаблонов для типового (токены Telegram, ключи вида
`sk-…`, `Bearer`, почты, телефоны, ИНН, IP, домены, пути с именем
пользователя) плюс собственный список слов для того, что шаблоном не
поймать: названия компаний, фамилии, внутренние имена систем.

## Формат результата

- `имя.log.anon` — обезличенная копия, которую не страшно показать;
- `anon.map.json` — словарь замен, остаётся у владельца;
- `ответ.restored.txt` — ответ постороннего с подставленными настоящими
  значениями;
- отчёт на экране: что и сколько скрыто, по типам, и что осталось
  подозрительного после проверки.

## Минимальный функционал (MVP)

Первая версия:

- веб-страница, работающая локально: перетащил файл — получил обезличенную
  копию, словарь и отчёт;
- обратная подстановка: вставил ответ, получил его же с настоящими данными;
- проверка «что осталось» — прогон готового файла по тем же шаблонам, чтобы
  поймать пропущенное до отправки;
- свой список слов — компании, фамилии, внутренние названия;
- работа из командной строки для тех, кому удобнее так;
- скилл для Claude Code: обезличить, разобрать, вернуть обратно.

Дальше, за пределами MVP: разбор архивов и PDF, профили правил под отрасли,
проверка на стороне сервера для команд.

## Технологии

- **Python 3.11+, только стандартная библиотека.** Ни одной внешней
  зависимости: `http.server` для локального интерфейса, `re` для шаблонов,
  `json` для словаря, `argparse` для командной строки. Сделано намеренно —
  инструмент для секретов не должен тянуть за собой чужой код, а запуск
  сводится к `python app.py` на любой машине.
- **Интерфейс** — одна HTML-страница без фреймворков и без интернета:
  ни одного внешнего запроса, всё считается локально.
- **Формат словаря** — JSON, читаемый человеком.
- **Тесты** — `unittest` из стандартной поставки.

Отдельное требование, вытекающее из назначения: **ни один файл не покидает
машину**. Сервер слушает только `127.0.0.1`, страница не делает внешних
запросов, ничего никуда не отправляется.
